# Controlled dependency batches

## Batch 1: `tmp` path validation

- Direct runtime dependency: `tmp` 0.2.5 → 0.2.7. The root manifest pins 0.2.7 exactly; the lockfile changes only that package entry and its root declaration. Bundled transitive copies are outside this batch.
- Reason: the upstream [path traversal advisory](https://github.com/raszi/node-tmp/security/advisories/GHSA-ph9p-34f9-6g65) affects earlier releases including 0.2.5; a [follow-up advisory](https://github.com/raszi/node-tmp/security/advisories/GHSA-7c78-jf6q-g5cm) identifies a non-string bypass in 0.2.6 and names 0.2.7 as patched. The [0.2.7 release](https://github.com/raszi/node-tmp/releases/tag/v0.2.7) remains the registry latest at review.
- Compatibility review: repository call sites use `dirSync({ unsafeCleanup: true })` with generated names. Both 0.2.5 and 0.2.7 pass default-directory, nested-content, repeated-cleanup behavior in a focused local probe. The 0.2.7 tarball matches the registry and lockfile SHA512. A focused 0.2.7 probe rejects string traversal and non-string `prefix`, `postfix`, and `template` values (12 cases) without creating files outside the intended directory.
- Required gate: fresh `npm ci`, build, offline contracts including the new path-validation check, Jest, and packed consumer passed on hosted Node 24 Windows/Linux in [review run 36794351524](https://github.com/evan-hyer/sfp-community-maintenance/actions/runs/36794351524). The [full-container run 36794348891](https://github.com/evan-hyer/sfp-community-maintenance/actions/runs/36794348891) passed. Optional Node 26 diagnostic jobs failed as expected and do not extend the support policy. Batch accepted at `99717003`.

## Batch 2: `simple-git` unsafe configuration hardening

- Direct runtime dependency: `simple-git` 3.19.1 -> 3.36.0, the latest 3.x release at review. The 4.x migration remains in the Git/network utility batch because `src/core/git/GitIdentity.ts` imports the removed `simple-git/promise` path.
- Reason: the upstream [case-insensitive `protocol.allow` advisory](https://github.com/advisories/GHSA-r275-fr43-pm7q) affects 3.19.1 and is patched in 3.32.3. The [3.36.0 release](https://github.com/steveukx/git-js/releases/tag/simple-git%403.36.0) also hardens exploitable configuration keys and task environment variables. The baseline local probe rejected lowercase `protocol.allow` but accepted uppercase `PROTOCOL.ALLOW`.
- Compatibility review: the existing Git and release contracts exercise this package's public API. A focused offline contract requires lowercase, uppercase, and mixed-case unsafe config keys to fail in the library before spawning Git. Keep the existing default import and `simple-git/promise` path until the 4.x migration.
- Required gate: the focused isolated 3.36.0 security/status probe, syntax, and diff checks pass. Clean hosted [review run 37139520514](https://github.com/evan-hyer/sfp-community-maintenance/actions/runs/37139520514) passes required Windows and Ubuntu Node 24 jobs, including source, contracts, Jest, packed consumer, and aliases; [full-container run 37139516676](https://github.com/evan-hyer/sfp-community-maintenance/actions/runs/37139516676) passes. Optional Node 26 diagnostics still fail outside the support policy. Batch accepted at `eaeb8450`.

## Batch 5: `fast-xml-parser` v5 migration

- Direct runtime dependency: `fast-xml-parser` 4.5.0 -> 5.11.2, the registry latest stable at review. This is a major migration within the XML/config utility group.
- Reason: the upstream [DOCTYPE entity-name advisory](https://github.com/NaturalIntelligence/fast-xml-parser/security/advisories/GHSA-m7jm-9gc2-mpf2) affects 4.5.0 and is patched in 4.5.4. The [XMLBuilder comment/CDATA advisory](https://github.com/advisories/GHSA-gh4j-gqv2-49f6) affects all 4.x and is patched in 5.7.0. The [5.11.2 release](https://github.com/NaturalIntelligence/fast-xml-parser/releases/tag/v5.11.2) includes later parser fixes. A 4.x bridge would leave the builder advisory unresolved.
- Compatibility review: application code parses settings and destructive manifests and builds entitlement XML. Isolated 4.5.0 and 5.11.2 probes produce identical settings/manifest structures and formatted entitlement XML. A new offline contract fixes those shapes and entity decoding; a separate unused parser import in `CustomFieldFetcher` is left for later cleanup.
- Transitive deferral: the lockfile still contains vulnerable nested parser copies: `@aws-sdk/core` 5.2.5, `@salesforce/packaging` 4.5.7, `@salesforce/source-deploy-retrieve` 4.5.3, and `@salesforce/source-tracking` 4.5.1. These leave the audit's critical parser finding in place even though the root copy is patched. The Salesforce-family/network SDK batches own their removal through compatible parent upgrades; review the audit nodes and packed graph at those batches. Do not force 5.x under parents declaring 4.x or exact 5.2.5.
- Required gate: the isolated XML contract passes on 5.11.2. Clean hosted [review run 37142587695](https://github.com/evan-hyer/sfp-community-maintenance/actions/runs/37142587695) passes required Windows and Ubuntu Node 24 jobs, including packed consumers; [full-container run 37142583079](https://github.com/evan-hyer/sfp-community-maintenance/actions/runs/37142583079) passes. - Direct runtime dependencies: root `glob` 10.4.2 -> 13.0.6 and internal `sfprofiles` `glob` 10.3.3 -> 13.0.6, the registry latest stable at review. Both declarations are pinned exactly.
- Reason: the [glob CLI command-injection advisory](https://github.com/advisories/GHSA-5j98-mcp5-4vw2) affects 10.4.2 but not the library `globSync` API used by this project. The [upstream changelog](https://github.com/isaacs/node-glob/blob/main/changelog.md) records Node 20 minimum in v11 and extraction of the CLI to `glob-bin` in v13. The declared Node 24 runtime is supported; no repository source or script invokes glob's CLI.
- Compatibility review: all six root application imports and the internal `sfprofiles` import use `globSync`, which v13 retains. Isolated Windows probes of 10.4.2 and 13.0.6 matched for artifact ZIP/TGZ extglobs, Apex class files, metadata XML, and profile directory patterns. A new offline contract fixes artifact and profile-directory matching under a path with spaces; existing artifact, Apex, and profile tests cover consuming behavior.
- Lockfile/packaging review: v13 requires `minimatch` 10.2.6 and `path-scurry` 2.0.2 with their nested matcher/cache packages. The old `sfprofiles` glob subtree leaves the lockfile; `rimraf` retains a separate patched `glob` 10.5.0 due its 10.x range. Shared `minipass`, `jackspeak`, and `package-json-from-dist` move within compatible ranges. The updated lockfile audit has no glob finding (88 findings remain elsewhere). v13 and several transitives declare BlueOak licenses; the inherited `Third Party Notices.md` needs reconciliation against the delivered bundle in the final packaging audit.
- Required gate: inspect the v13 lockfile graph and audit, then pass the focused contract, clean hosted Windows/Ubuntu Node 24 source and packed-consumer checks, and full container before accepting the batch.
